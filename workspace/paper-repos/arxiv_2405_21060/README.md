# Transformers are SSMs: Generalized Models and Efficient Algorithms Through Structured State Space Duality

**Paper:** Tri Dao and Albert Gu (2024), [arXiv:2405.21060](https://arxiv.org/abs/2405.21060).
**Code:** independent PyTorch reproduction written from the paper. This is not the authors' repository and does not claim access to their original run logs or checkpoints.

> **Contribution note.** The scaffold in this directory (model, data pipeline, training/evaluation code, tests, configs, SIR) was generated by an AI assistant and committed under a bot identity so that machine-written work is clearly flagged. Paper-scale experiment runs and results are to be added by the assigned human contributor in their own commits.

## Reproduction status

This repository implements SSD in recurrent, quadratic (dual / attention-like), and chunked forms following Listing 1 (exact float64 equivalence including initial and final states), the Mamba-2 block with parallel projections, depthwise conv, gated RMSNorm, and O(1)-state step decoding that matches the chunked forward, a Mamba-2 LM, and an MQAR associative-recall training task.

**The paper-scale experiments have not been run here.** The authoring workspace is CPU-only (2 cores, ~1 GB RAM). The unit tests and the smoke configuration verify code paths and invariants, not the paper's empirical claims. Do not report smoke metrics as reproduction results. Paper-scale runs need: A100/H100 GPUs for LM scaling; the MQAR config fits on one GPU.

## What the paper does

With A restricted to a scalar per head, a selective SSM unrolls to a matrix multiplication with a 1-semiseparable mask, which is exactly masked linear attention with a decaying causal mask. The SSD algorithm splits the sequence into chunks: within a chunk it uses the quadratic form, and between chunks it passes low-rank states with a short recurrence. Mamba-2 builds a block around this layer with parallel input projections, a multi-head structure, and extra normalisation.

## Model and training defaults

- **Block:** expand 2, head dim 64, d_state 64, conv kernel 4, chunk 64, ngroups 1.
- **Optimizer:** AdamW (0.9, 0.95), wd 0.1 (none on A_log, D, dt_bias, norms).

## Important assumptions and limits

- Only the 2–8× core-layer speed-up is quoted; read MQAR (Fig. 8), scaling (Fig. 9) and zero-shot (Table 1) targets from the paper.
- Pure PyTorch einsum implementation of Listing 1; no Triton kernels.
- A ~ -U[1,16], dt in [1e-3, 0.1] log-uniform, D = 1 (reference implementation defaults).
- AdamW (0.9, 0.95), wd 0.1, warmup-cosine; LR is an assumption.

See [`sir.json`](../../sir-registry/arxiv_2405_21060/sir.json) and the [architecture plan](../../sir-registry/arxiv_2405_21060/architecture_plan_summary.md) for structured assumptions and confidence annotations, and [`comparison/`](comparison/) for the paper-vs-reproduction table.

## Install

Python 3.10+ is required. For CPU-only PyTorch install the CPU wheel first; then install the project and tests:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e '.[test]'
pytest -q
```

For CUDA, install the PyTorch build matching your driver, then `python -m pip install -e '.[test]'`.

## Paper-scale protocol

```bash
PYTHONPATH=src python -m mamba2_repro train --config configs/paper.json --output-root results/runs
```

LM scaling needs a tokenized Pile loader; speed benchmarks need GPU kernels. Runs with `--steps` are truncated and must not be reported.
