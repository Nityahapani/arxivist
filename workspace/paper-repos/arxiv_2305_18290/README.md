# Direct Preference Optimization: Your Language Model is Secretly a Reward Model

**Paper:** Rafael Rafailov, Archit Sharma, Eric Mitchell, Stefano Ermon, Christopher D. Manning, and Chelsea Finn (2023), [arXiv:2305.18290](https://arxiv.org/abs/2305.18290).
**Code:** independent PyTorch reproduction written from the paper. This is not the authors' repository and does not claim access to their original run logs or checkpoints.

> **Contribution note.** The scaffold in this directory (model, data pipeline, training/evaluation code, tests, configs, SIR) was generated by an AI assistant and committed under a bot identity so that machine-written work is clearly flagged. Paper-scale experiment runs and results are to be added by the assigned human contributor in their own commits.

## Reproduction status

This repository implements the DPO loss (Eq. 7) and implicit reward, masked sequence log-probabilities for causal LMs, the gradient weighting term, a full SFT → preference sampling → DPO pipeline on a synthetic controlled-generation task with a known Bradley-Terry ground truth, and reward/KL evaluation. A test verifies that minimising the expected DPO loss recovers π* ∝ π_ref·exp(r/β).

**The paper-scale experiments have not been run here.** The authoring workspace is CPU-only (2 cores, ~1 GB RAM). The unit tests and the smoke configuration verify code paths and invariants, not the paper's empirical claims. Do not report smoke metrics as reproduction results. Paper-scale runs need: multiple A100-class GPUs for the GPT-J / Pythia-2.8B experiments; the synthetic task runs on CPU.

## What the paper does

DPO reparameterises the reward through the closed-form optimal policy of KL-regularised reward maximisation, so the Bradley-Terry likelihood of preferences becomes a function of the policy and a frozen reference. Training is a binary cross-entropy on the difference of log-ratio margins between preferred and dispreferred completions.

## Model and training defaults

- **β:** 0.1.
- **Optimizer:** RMSprop, LR 1e-6, batch 64, 150 linear warmup steps.
- **Reference:** frozen copy of the SFT policy.

## Important assumptions and limits

- No numeric targets are hard-coded; read targets from Figure 2 (reward/KL frontier), Figure 3 (TL;DR and HH win rates) and Table 2 of the paper.
- A synthetic controlled-generation task with a known reward stands in for IMDb + sentiment classifier.
- Smoke SFT uses uniform random tokens.

See [`sir.json`](../../sir-registry/arxiv_2305_18290/sir.json) and the [architecture plan](../../sir-registry/arxiv_2305_18290/architecture_plan_summary.md) for structured assumptions and confidence annotations, and [`comparison/`](comparison/) for the paper-vs-reproduction table.

## Install

Python 3.10+ is required. For CPU-only PyTorch install the CPU wheel first; then install the project and tests:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e '.[test]'
pytest -q
```

For CUDA, install the PyTorch build matching your driver, then `python -m pip install -e '.[test]'`.

## Quick smoke test

A deliberately tiny configuration that checks the pipeline end to end; it is **not** a paper result.

```bash
PYTHONPATH=src python -m dpo_repro smoke --config configs/smoke.json --output-root results/smoke
```

## Paper-scale protocol

```bash
PYTHONPATH=src python -m dpo_repro train --config configs/paper.json --output-root results/runs
```

The provided `configs/paper.json` applies the paper's optimisation hyperparameters to the synthetic task. Running the IMDb / TL;DR / HH experiments requires Hugging Face models and datasets. Runs with `--steps` are truncated and must not be reported.
